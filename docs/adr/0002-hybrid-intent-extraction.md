# ADR-0002. Гибридный разбор запроса: правила + LLM

**Статус:** принято

## Контекст
LLM хорошо понимает свободный текст, но: медленный (секунды), платный, иногда недоступен и может «придумать» бюджет или даты. Правила (regex) быстрые и точные там, где срабатывают, но не знают всех городов и формулировок.

## Решение
1. Правила выполняются **всегда** и помечают каждое поле как *явное* (найдено в тексте) или *допущение* (значение по умолчанию).
2. LLM (GigaChat или YandexGPT через порт `LlmClient`) вызывается под circuit breaker и возвращает JSON.
3. `IntentMerger`: явные поля правил не перезаписываются; допущения заменяются валидными значениями LLM; множества объединяются; невалидные значения LLM отбрасываются по полям.
4. Любой сбой LLM → результат правил с пометкой для пользователя.

## Последствия
- Демо и прод работают без LLM; LLM повышает полноту, но не надёжность-критичен.
- «Галлюцинация» бюджета невозможна, если пользователь назвал бюджет.
- Кэш ответов в Redis экономит вызовы LLM на повторных запросах.
- Минус: два источника истины требуют тестов на слияние (`IntentMergerTest`).
