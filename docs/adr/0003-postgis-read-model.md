# ADR-0003. PostGIS и read-модель на JdbcClient

**Статус:** принято

## Контекст
Поиск фильтрует по гео («15 минут пешком до Эрмитажа»), выбирает самый дешёвый подходящий тариф и считает расстояния до достопримечательностей. Через JPA это N+1 запросов или сложный Criteria API.

## Решение
- Гео-данные в `GEOGRAPHY(POINT, 4326)`, GiST-индексы, `ST_DWithin` / `ST_Distance` в метрах.
- Чтение — один SQL через `JdbcClient`: `JOIN LATERAL` для лучшего тарифа, подзапросы `ARRAY(...)` для удобств и мест рядом. SQL собирается из фиксированных фрагментов, значения — только параметрами.
- Запись (бронирования) будет на JPA — CQRS-lite: разные модели для чтения и записи.
- «Пешком N минут» → радиус по прямой с коэффициентом извилистости 1.25 и скоростью 80 м/мин. Кандидаты берутся с запасом 1.5×, чтобы показать компромиссы.

## Последствия
- Один запрос к БД на поиск, предсказуемый план выполнения.
- Мягкие критерии оцениваются в Java чистыми функциями и тестируются без БД.
- Минус: SQL приходится проверять интеграционными тестами на настоящем PostGIS (Testcontainers).
